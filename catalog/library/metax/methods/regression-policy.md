# 算子替换正确性判定

版本：2026-11-23。观测集合与机器可读规则见 [configs/regression_policy-v1.json](../../../../experiments/evidence/metax/glm53/repeatability_20261123/configs/regression_policy-v1.json)；详细实测见 [REPORT.md](../../../../experiments/evidence/metax/glm53/repeatability_20261123/REPORT.md) 和 [evidence/tensor_summary.json](../../../../experiments/evidence/metax/glm53/repeatability_20261123/evidence/tensor_summary.json)。当前没有候选算子被验收；通过 HumanEval 功能检查也不等于局部数值等价成立。

## 进入比较前

固定模型/权重 revision、tokenizer/template、数据/任务 ID、每题输入 token、解码与停止条件、TP8/runner/eager/调度配置、请求顺序、评分原始测试与资源限制。只允许改变登记的候选算子代码及其必要构建产物。实际镜像/依赖、导入源码、每卡状态、命令和结果都要留证；缺失、哈希不符或基础设施错误记为 `invalid`，不能算作模型失分，也不能跳过题目后计算分数。

原 HumanEval v1 的 153/164 是历史参考，不应直接变成“总分不少于 153 就通过”的规则。候选前先按相同条件交错运行 B0/C，各至少三个全新模型进程，使用完整 164 题；同进程重复不能充当三个独立样本。32 题只做快速筛查，本轮没有重复完整 164 题，不能据此冻结全量的稳定题集合。

## 功能门槛

1. **稳定通过题不得退化**：在三个同期 B0 进程都通过的题，候选三个进程也必须全部通过。任何一题退化即 `fail`；其他题改善不能抵消。
2. **波动题单独判断**：逐题比较通过次数。如果候选通过次数下降，记为 `inconclusive`，保留输出并开展更多配对复测/原因定位，不能用总分相抵后自动通过，也不能无限重试直到出现好结果。加测轮数须先固定。
3. **总分保护**：候选最差轮与三轮总通过数不低于同期 B0 的对应值。这是工程筛查，不是统计学的非劣性证明；仅总分下降而没有稳定题退化时先记为 `inconclusive`。
4. 每题一次生成，不按测试修改代码、补缩进、重采样；固定提取器。保留解析失败、运行失败、超时及输出截断标记。沿用无网络 CPU 隔离评分。

[harness/check_functional_gate.py](../../../../experiments/evidence/metax/glm53/repeatability_20261123/harness/check_functional_gate.py) 实现上述功能门槛，校验三轮、任务集合、请求顺序、采样/环境设置、输入 token manifest、评分器/镜像指纹及生成文件哈希。输入/测试材料的全局哈希和真实独立进程证据仍须先按实验清单核对。输出 `pass_functional` 仅代表功能层通过；还必须通过下面的局部与模型数值层。

## 局部算子门槛

- 每个 operator ID 单独冻结 shape、dtype、布局/stride、量化格式与 scale、累加类型、输入输出别名、状态更新和边界情况。索引、mask、整数精确语义、量化舍入/饱和规则、argmax 的并列最大值规则必须精确符合契约；不能只比较最终文本。
- 浮点算子使用独立 FP32/FP64 参考或可解释的高精度实现；记录 max-abs、RMSE、相对误差及尾部误差，覆盖实测热 shape、极值、零值、非连续布局和各 rank。先校准 B0 自误差，再在看到候选结果前冻结每个算子的 atol/rtol 和上限。没有算子契约或预先冻结的数值阈值，状态为 `inconclusive`，禁止用统一“INT8 允许 1%”替代。
- NaN/Inf、新的越界/内存错误、错误 dtype/shape、错误状态生命周期、整数语义变化直接失败。候选未覆盖的输入必须走已验收的 B0 fallback，并记录实际命中覆盖率。

## 模型数值门槛

在固定 token 前缀下比较相同位置的 logits 和必要中间状态，不比较已发生自由生成分叉之后的 logits，因为那时两边输入已不同。区分 prefill 与 cached decode 两种计算路径，分别校准，不能把一种路径的阈值直接用于另一种。

使用同期 B0 多次运行估计同条件的数值波动，并保存完整 logits/张量和 top-1/top-2 间隔。候选的数值误差预算必须在候选测试前登记，同时受局部参考误差和端到端功能门槛约束；有限次 B0 的最大差值只是观测值，不是全局误差上界，不能机械放大后作为所有算子的通用容差。

本次9个固定前缀、两个诊断进程各三遍的162组同路径比较，完整 logits 与已采集模块输出都逐值相等；这是可用的严格诊断 fixture，**不表示所有候选浮点算子的容差必须为0**。跨 prefill/cached 路径的观测最大 logit 差2.1953125属于不同计算路径，不纳入同路径噪声预算。108次诊断的 top-1/top-2 间隔0.125～1.25、无并列最大值，也不构成历史分歧原因的证明。本轮没有冻结通用数值 ε，具体算子缺少预登记阈值时不能验收。

若已建立可信的逐 logit 误差上界 ε，则参考 top-1/top-2 间隔大于 2ε 的位置应保持 argmax；否则失败。间隔小于等于 2ε 的位置属于敏感决策点，token 翻转需要记录并进入功能/数值联合判断，不能仅因此自动失败或自动放行。没有经过验证的 ε 时，该公式只用于定位，不给出验收证明。

因此，**自由生成 token 全等作为诊断指标，不作为所有请求统一的硬门槛**；已证实严格稳定、且配置/路径完全相同的固定用例可以单独设严格门槛。完整 HumanEval 的逐题功能门槛仍然生效。

## 验收输出

候选结果必须分别列出 `invalid / fail / inconclusive / pass`，附稳定题退化清单、波动题通过次数、首处分歧、相同前缀 logits、局部算子误差及覆盖率。只有实验完整性、局部数值、模型数值和全量功能四层均满足预先冻结的条件，才允许进入性能收益验收。性能基线另测，不复用此处的带 hook 或精度评测耗时。
