3.7.8 限制和注意事项
动态并行保证了本文档中描述的所有语义。但是，某些硬件特性和软件实现会限制使用设备运行时的程
序规模、性能和其他属性。
3.7.8.1 内存限制
MXMACA 设备运行时的驱动软件为各种管理目的保留内存，特别是为跟踪和保存待处理的父子网格状态
而保留内存。用户可配置此保留项的大小，但可能带来某些启动限制。有关详细信息，请参阅下面的 配
置选项。
核函数启动池槽位数
当核函数启动时，将跟踪所有相关的配置和参数数据，直到核函数完成。该数据存储在系统管理的启动
池中。
可通过从主机调用函数 mcDeviceSetLimit 并指定 mcLimitDevRuntimePendingLaunchCount
来配置启动池（固定大小）的大小。

mcLimitDevRuntimePendingLaunchCount 控制核函数启动相关资源的数量，同时分配对应
大小的缓冲区，存放有依赖关系的核函数相关资

mcLimitStackSize 控制每个 GPU 线程的栈内存大小（以字节为单
位） 。 MXMACA 驱动程序根据需要自动增加每次核
函数启动的每线程堆栈大小。每次启动后，此大
小不会重置回原始值。
mcLimitMallocHeapSize 控制 GPU 堆大小（以字节为单位） 。MXMACA 设
备运行时在启动核函数时需要一些额外的内存开
销，会隐式使用一部分堆内存，如果堆内存不足，
可能导致启动核函数失败。
内存分配和生命周期
函数 mcMalloc 和 mcFree 在主机和设备环境之间具有不同的语义。当从主机调用时，函数 mcMalloc
从未使用的设备内存中分配一个新区域。当从设备运行时调用时，这些函数映射到设备端 malloc 和
free 。这意味着在设备环境中，可分配的总内存被限制为设备 malloc 堆大小，该大小可能小于可用
