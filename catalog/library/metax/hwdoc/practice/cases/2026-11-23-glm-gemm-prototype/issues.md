# GEMM原型期间的未闭环设备问题

## GPU6不可用阻断八卡模型验证

观察日期2026-11-23。本轮宿主驱动3.10.14；历史基线3.8.30。模型使用冻结镜像9bbf20db、vLLM5df63a72、MetaX0962c873加已有修复。驱动/宿主重启发生在进入本轮前，本任务未变更驱动、重启或重置设备。

内核报告GPU6（0000:5b:00.0）的MetaXLink不可纠正错误EID0x2119、AER Unsupported Request，设备状态变为Not Available。完整TP8模型停在通信初始化，尚未权重加载/候选注入，不能归因于候选GEMM。先前8卡56组单算子通过只描述故障前观察。

停止本次实验容器后GPU6仍不可用。诊断exec临时设置MCCL_P2P_DISABLE=1，rank6仍在队列创建时ioctl失败并SIGSEGV，all-reduce未完成。关闭P2P没有恢复设备；ACS参数只读记录，未修改。变量文档依据见实验报告所引MCCL编程指南V08物理PDF32页§4.2.2.21。

最终只停止`glm53-gemm-v1`，无GPU进程，其他7卡Available、卡6Not Available。旧4容器身份、运行状态和挂载内容未变。设备根因、驱动与错误的因果关系均未知；不要因ACS警告或驱动变化就断言原因。

证据：`evidence/hardware_issue_summary.json`包含审阅后的必要事件、时间域说明及远程原日志路径/SHA256；原始内核日志不批量入库。完整单卡结果见[案例](case.md)，仅证明真实权重+合成激活的局部替换。

后续需要维护方恢复设备并先做最小通信检查；通过后才在新目录继续完整模型对照。此记录不授权自动复位GPU、改驱动/PCIe或重启主机。
