# 推理验收与基线冻结

本例最终通过真实权重的 TP8 文本生成，范围为 V2 runner、4096 上下文、单序列、同步调度、eager。验收脚本、结果和资产哈希见[案例](../cases/2026-11-22-glm53-w8a8-tp8/README.md)。加载成功、单个算子正确和服务有响应各自只证明一个环节。

## 分层验证

1. 权重：固定仓库 revision，核对文件数、大小、哈希、分片索引、量化配置与 tokenizer。本例 59/59 文件校验，47 个分片；保留原 metadata 异常记录，不擅自改原权重。
2. 环境：实际导入来源、8 卡发现、各卡 BF16 计算、MCCL 集合通信及依赖一致性。
3. 局部适配：核对 native schema、Tensor/tuple 接口契约、权重与 scale 的加载所有权；使用独立 CPU 参考及兼容分支回归。
4. 真实生成：至少包括自然语言、明确答案和长前缀检索，检查输出、结束原因、有限数值与 worker 来源。本例全部正常停止；不以固定 token 数或输出哈希作为通用正确性标准。
5. 遇到错误输出：保留失败配置，用逐层数值追踪定位首次异常，区分加载、计算、缓存与调度。本例多个原语数值检查通过，仍存在 MLA INT8 scale 未初始化；不能据原语通过推断模型正确，也不能把未证实的 KDA 假设写成根因。

## 本例复现入口和边界

在已恢复且有资源执行的目标服务器上：

```bash
bash /home/metax/glm53-vllm032/scripts/run_inference.sh
```

脚本有任务容器标签检查、锁和已有 worker 检查。它执行离线 smoke，不启动常驻 HTTP 服务。采样为 temperature=1、top_p=0.95、seed=0、最大输出 1024，使用聊天模板和 reasoning_effort=low。结果为中文介绍正常、算术回答 2、2433 输入 token 中找出“青松”。生成耗时含 JIT/初始化影响，不能作为吞吐基准。

V1 混合调度曾出现非法显存访问，最终 scale 修复后未重新验证 V1。并发、异步调度、CUDA graph、长上下文、多模态、SGLang 对照和性能指标均未验收。后续一次改变一个条件，保留已通过基线和失败证据。

## 冻结和回放

停稳本任务 worker 后记录容器状态、包清单、源文件哈希及补丁，将依赖层冻结为 image ID；另存源码（包括新增未跟踪补丁文件、所需编译产物）和脚本归档。原始凭据、代理配置和模型不进入归档。不要仅保存 git diff：它可能漏掉新增文件。

本例 tar 遇到 root 所有的缓存目录，改为排除开发缓存、写 `.partial`、校验后再改名。Docker 29 冻结较大软件层耗时约 27 分钟，不能把本地压缩时间当下载故障。`--pause=false` 的弃用警告混入 stdout，原脚本把警告连同 image ID 一起解析，导致后续 inspect 失败；commit 实际成功。按确切 tag 检查 ID 和标签后确认产物，脚本改用 `--no-pause` 并提取唯一 SHA256 行。

新建一次性、无网络容器验证实际源路径、8 卡发现和 `pip check`。本例这三项通过，但**没有在新容器再跑完整模型生成**；完整 TP8 生成是在原独立工作容器通过。回放记录必须按这个范围表述，后续全面复现应另存新日期证据。
