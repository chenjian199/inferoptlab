# Mihomo 下载代理的配置与验证

本例在目标服务器独立任务目录运行 Mihomo v1.19.34，为下载命令提供认证回环代理。它改善了下载链路，但没有使原始大镜像完整下载。验证记录见[代理证据](../cases/2026-11-22-glm53-w8a8-tp8/evidence/proxy_runtime.json)，适用范围为 2026-11-22 的这台服务器及所测端点。

## 私密配置与运行

在目标服务器的交互式终端执行已有管理器。以下是本案例入口，不会由文档构建执行：

```bash
python3 /home/metax/glm53-vllm032/proxy/manage_proxy.py configure
python3 /home/metax/glm53-vllm032/proxy/manage_proxy.py start
python3 /home/metax/glm53-vllm032/proxy/manage_proxy.py status
```

`configure` 中粘贴 Clash/Mihomo 格式的 HTTPS 订阅，输入不回显；不复制实际地址到本文或脚本参数。私密目录权限 700、配置 600，HTTP/SOCKS 监听 `127.0.0.1:17890`，控制器监听 `127.0.0.1:19090`，均要求认证。关闭 LAN 访问、TUN 和代理 DNS 接管。本例没有安装自动启动系统服务。

管理器部署在远程，本地源码为 `glmf/deploy032/manage_proxy.py`；私密配置未复制到知识库。代码入口、源码哈希和相关下载脚本的归档状态见[资产清单](../cases/2026-11-22-glm53-w8a8-tp8/artifacts.json)。移植时先核对管理器实现和运行用户，不把这里的路径视为通用安装程序。

## 验证与使用

1. 核对监听地址、权限和进程。无认证访问代理应返回 407，无认证访问控制器应返回 401；这两个拒绝响应是认证控制有效的证据。
2. 通过管理器在本机私密读取认证信息，按下载进程使用代理；不要打印完整带认证的代理 URL。逐端点记录是否可达、少量下载的速率，再验证大文件和哈希。
3. 对比直连和代理时保持对象、范围和超时可比。节点测试通过不保证 registry 长连接稳定；不要依据小文件速率承诺大镜像下载时间。
4. 本例未修改全局代理或 Docker daemon 配置，也未重启 Docker。宿主机回环地址在普通桥接容器内不指向宿主机；不要为方便而开放 LAN 或把私密配置挂载进推理容器。

## 停用和恢复

下载完成或本次授权工作结束后，可在目标服务器执行管理器的 `stop` 子命令，并清理当前下载进程使用的代理变量。再次使用前重新检查 `status`；历史“运行中”不表示现在仍运行。保留受限权限的配置由用户管理，不将订阅和认证值放入镜像或共享归档。
