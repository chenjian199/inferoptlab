# ADR-0001：首版架构决策

状态：建议采纳。日期：2026-11-20。

## 决策 1：模块化单体控制端，独立 Worker

保留一套领域对象与状态机。首版使用本地 CLI 与可持久化控制流程，GPU 执行放 Worker；后续只在并发、多用户或部署边界确有需要时拆服务。

## 决策 2：优化器与最终验证器独立

优化器可以生成候选和执行开发测试。最终评分规则、验收输入、测量口径及正式记录由独立验证器管理，候选导入初始状态为 unverified。

## 决策 3：聚合与 P/D 共享候选对象

部署模式是条件搜索维度。实际资源通过角色与设备映射核算，比较固定相同预算。能力未验证或不支持的分支保留原因，不静默回退。

## 决策 4：机制库保持开放

通信、内存、算子等都是标签。未知机制进入未解释问题队列，可通过最小区分实验和新机制卡扩展。不能要求所有问题被强行归入已有类别。

## 决策 5：证据分层且不可覆盖

预测、Agent 自报、独立实测、派生结果分开。Run 原始数据与失败记录保留；候选、环境、基线和验收规则有内容身份。最终报告说明已测范围，不声称全局最优。

## 决策 6：按能力验证，不按厂商品牌猜测

核心不依赖厂商 SDK。适配器返回 verified / unverified / unsupported 和明确范围。默认值、真实后端、KV 兼容性和并行组均需实际核对。

## 决策 7：配置搜索和代码优化都进入首条闭环

首版可以只支持一个真实平台，但必须能够导出并回接至少一个实现优化任务。否则产品会退化为参数扫描器，无法满足本项目端到端自动优化目标。

## 决策 8：外部项目版本隔离

KDA 工作流、AISim 预测器和框架 benchmark 都经适配器接入。锁定 commit、包和数据版本；main 文档不等于安装环境。核心对象不继承第三方易变对象。

## 决策 9：固定点收益与重新寻优收益分开

一个代码改动先在固定配置和负载下复测，再以相同搜索预算重新寻优。独立报告两种收益；组合候选重新验收，禁止加总单项加速比。

## 决策 10：完整契约是复现起点

保留 Study → Candidate → Trial → Run → Measurement → Acceptance 的关联。契约、协议与数据 hash 同时冻结。改测试语义必须产生新的比较集合和基线。
